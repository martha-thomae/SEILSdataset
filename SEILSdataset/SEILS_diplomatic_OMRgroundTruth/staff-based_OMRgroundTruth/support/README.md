# Retrieving the staff-based OMR ground truth

This implied generating staff-region images and staff-region sub-tokenised Humdrum \*\*mens encodings. The processes to generate each are detailed in the following two sections.

## A) Generating the images

The resources related to the images are in the [`images`](./images) folder.

### 1. Particellas PNG files

The PDFs from [`particellas_original`](../../particellas_original) folder have been converted into PNGs. Most of them had a size of 1200 x 813 pixels, except for a few with size of 2550 x 3300 pixels. These few had extra white areas on top and bottom of the image. We trimmed those using ImageMagick (`magick "$file" -trim`), resulting in an image size of 2550 x 1728 pixels. Then we resized these images to match the 1200 width of the rest of the images (`magick "$file" -resize 1200x`). The resulting PNGs are stored in [`images/particellas_PNGs`](./images/particellas_PNGs).

### 2. Staff regions

The PNGs generated in the previous step were uploaded into [Label Studio](https://labelstud.io/quick-start/) to annotate their individual staff regions. The results of these annotations are stored in [`images/staff-regions`](./images/staff-regions).


## B) Generating the sub-tokenized \*\*mens encodings

The workflow for generating sub-tokenized mensural notation encodings from the original Humdrum mensural notation files of the particellas (stored in the [`particellas_codified`](../../particellas_codified) folder) consists of four stages:

**Extraction → Cleaning → Staff segmentation → Sub-tokenization**

Each stage is performed by a dedicated Bash or Python script. The output of each stage serves as the input to the next one. The four scripts and the four folders generated by each of them can be found in the [`code`](./code) folder.

#### Summary table

| Stage | Program/Script | Output folder (within `code` folder) | Contents |
| ----- | -------------- | ------------- | -------- |
| 1. Extraction | `extract_mens_spines.sh` | `extracted_mens_spines` | Extracted `**mens` spines from particellas |
| 2. Cleaning | `clean-mns.sh` | `cleaned_mens_spines` | Cleaned `**mens` spines |
| 3. Staff segmentation | `divide_into_staves.py` | `staff_segmented_mens` | `**mens` spines segmented into individual staves |
| 4. Sub-tokenization | `tokenizer.py` | `subtokenized_staff_segmented_mens` | Staff-segmented `**mens` files whose tokens have been divided into subtokens |

Details on each of the fours stages, follow below.

### 1. Extraction of `**mens` spines

[`extract_mens_spines.sh`](./code/extract_mens_spines.sh) – Bash script that extracts the `**mens` spine from each Humdrum mensural notation file (`.mns`) in the [`particellas_codified`](../../particellas_codified) folder. 

Each input file contains two spines corresponding to a given choral voice: one encoding the music (`**mens`) and another encoding the lyrics (`**text`). The script extracts the musical spine alone (`**mens`)---discarding the lyrics spine---and saves the resulting files in [`extracted_mens_spines`](./code/extracted_mens_spines), preserving their original filenames.

  - **Input:** Humdrum `.mns` files in `particellas_codified`.
  - **Output:** Files containing only the `**mens` spine, stored in `extracted_mens_spines`.


### 2. Cleaning of `**mens` spines

[`clean-mns.sh`](./code/clean-mns.sh) – Bash script that cleans the extracted `**mens` spines by removing tokens and token characters that are not relevant to the OMR process.
  
  - **Input:** Files in `extracted_mens_spines`.
  - **Output:** Cleaned files stored in `cleaned_mens_spines`.

The cleaning process removes the following elements:

- **Tokens unrelated to mensural notation:**
  - Time signature and tempo interpretations inherited from the modern transcriptions (Humdrum `**kern` files) from which the mensural files were generated (e.g., `*M4/4` and `*MM72`).
  - Humdrum syntactic elements: staff-label interpretations (starting with `*staff`), spine terminators (`*-`), comments (starting with `!`), null data tokens (`.`), and null interpretation tokens (`*`).
- **Characters encoding mensural rhythmic interpretation:** The `i` and `p` characters in note tokens, which indicate imperfect and perfect rhythmic values, respectively.
- **Empty key signature interpretations:** Tokens such as `*k[]`.

The following table lists the commands used for cleaning and describes their respective functions:

  | Command | What it does |
  | ------- | ------------ |
  | `'/^\*-/d'` | Deletes spine terminators (`*-`) |
  | `'/\*M/d'` | Deletes 'time signature' and 'tempo' interpretations |
  | `'/^\.$/d'` | Deletes null data tokens (`.`) |
  | `'/^\*$/d'` | Deletes null interpretation tokens (`*`) |
  | `'/^!/d'` | Deletes comments |
  | `'/^\*k\[\]/d'` | Deletes empty key signature interpretations (`*k[]`) |
  | `'/^\*staff./d'` | Deletes staff-label interpretations (starting with `*staff`) |
  | `'s/[ip]//g'` | Removes the `i` and `p` characters from data tokens (i.e., removes the rhythmic interpretation of mensural notes) |

**IMPORTANT:** The cleaning process also provides an **important fix** for the mensuration sign `C3/2` included in one of the chorales (_virchi_arsimentre_). This mensuration sign was encoded by two consecutive mensuration interpretation tokens: `*met(C)` and `*met(3/2)`. The `clean-mns.sh` merges these two tokens into a single `*met(C3/2)` token. The `*met(C3/2)` mensuration sign is handled correctly by the Verovio Humdrum Viewer when converting the Humdrum mensural file into Mensural MEI (it gets converted into `<mensur sign="C" num="3" numbase="2">`).[^1]


### 3. Staff segmentation

[`divide_into_staves.py`](./code/divide_into_staves.py) – Python script that divides each cleaned `**mens` spine into segments corresponding to the individual staves in the original source.

Each input file contains the cleaned `**mens` spine for a single choral voice. Staff breaks are indicated by the `=-` token, which the script uses to identify the boundaries between successive staves.

- **Input:** Cleaned `**mens` spines in `cleaned_mens_spines`.
- **Output:** Individual staff-based `**mens` segments, stored in `staff_segmented_mens`.


### 4. Sub-tokenization

[`tokenizer.py`](./code/tokenizer.py) – Python script that splits individual `**mens` tokens into smaller units (subtokens).[^2]

For example, the token `[s~g#` is sub-tokenized as `[ s ~ g #`, separating its constituent elements: the ligature start marker (`[`), the semibrevis note shape (`s`), the coloration marker (`~`), the pitch (`g`), and the accidental (`#`). This decomposition reduces the vocabulary size that the OMR model needs to handle.

- **Input:** Staff-segmented `**mens` files in `staff_segmented_mens`.
- **Output:** Sub-tokenized, staff-segmented `**mens` files, stored in `subtokenized_staff_segmented_mens`.



[^1]: The separate mensuration sign tokens would get converted into two `mensur` elements, `<mensur sign="C" modusmaior="2" modusminor="2" tempus="2" prolatio="2">` followed by `<mensur num="3" numbase="2">`, instead of one mensuration sign `<mensur sign="C" num="3" numbase="2">` with its own meaning, which can be provided through the `@modusminor`, `@tempus`, and `@prolatio` attributes.

[^2]: The tokenizer distinguishes between two types of ligatures: oblique ligatures, marked by `<` and `>`, and recta ligatures, marked by `[` and `]`.
